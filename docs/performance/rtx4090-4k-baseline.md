# Win11 + RTX 4090 的 4K 性能基线

本报告记录 TeachCut 第二阶段的首个可重复性能基线。测试机器为 Windows 11、RTX 4090 24GB、NVIDIA 驱动 610.47，使用 libopenshot 0.7.0、FFmpeg 8.1.2 和 3840×2160/30fps 合成素材。

## 结论

- 不需要把 8K 纳入日常开发基准；当前目标是用户实际会处理的 4K。
- 不应默认强制启用硬件解码。libopenshot 会把硬件帧复制回系统内存，在本次 4K H.264/HEVC 测试中 CPU 解码明显更快。
- RTX 4090 对导出有效：H.264、HEVC 和 AV1 NVENC 的完整输出链路均超过实时速度，并比软件 H.264 快约 60%。
- HEVC 和 AV1 原先不在 libopenshot 硬件解码白名单中；本分支通过可重复应用的原生补丁启用了二者，并验证不会再静默回退。
- 真实素材仍需要复测。合成片适合回归和比较，但不能覆盖相机长 GOP、10-bit、4:2:2、可变帧率和频繁跳转。

## 4K H.264 解码

每种模式连续读取 180 帧并重复三次，下表使用耗时中位数。

| 模式 | 硬件路径确认 | 解码 FPS | 实时倍数 |
|---|---:|---:|---:|
| CPU | 不适用 | 112.04 | 3.73× |
| NVDEC | 成功 | 45.57 | 1.52× |
| D3D11 | 成功 | 42.63 | 1.42× |

推荐：这类素材保持“硬件解码：关闭”。硬件路径虽然工作正常，但显存到系统内存的复制成本超过了解码收益。

## 4K 导出

测试读取 90 帧，并使用该素材实测最快的 CPU 解码作为输入。所有编码器使用相同的 45 Mb/s 名义码率，因此文件大小只能用于诊断，不能视为同画质比较。

| 编码器 | 完整输出 FPS | 实时倍数 | 相对软件 H.264 |
|---|---:|---:|---:|
| libx264 | 22.58 | 0.75× | 基准 |
| h264_nvenc | 36.58 | 1.22× | 快 62% |
| hevc_nvenc | 36.34 | 1.21× | 快 61% |
| av1_nvenc | 35.55 | 1.19× | 快 57% |

推荐用途：

- 默认快速交付：`H.264 NVENC`，兼容性最好。
- 更小文件或本地归档：`HEVC NVENC`，播放端必须支持 HEVC。
- 新平台试验：`AV1 NVENC`。显式 VBR 后短片实际码率已接近 45 Mb/s 目标，但兼容性和真实画质仍需素材验证，因此预设保留实验性标记；必须保留 H.264 兼容副本，不把 AV1 当唯一母版。

## HEVC/AV1 解码修复

修复前，4K HEVC 即使选择 NVDEC/D3D11，`HardwareDecodeSuccessful()` 仍返回 `false`，实际静默回退 CPU。加入 HEVC/AV1 白名单后：

- 4K HEVC：NVDEC 和 D3D11 均返回硬件成功；但 CPU 仍约 139.6 FPS，NVDEC 约 50.5 FPS，因此继续推荐 CPU。
- 4K AV1：NVDEC 和 D3D11 均返回硬件成功；三种路径约 103～105 FPS，差异太小，不足以改变默认值。

## 复测命令

生成合成 4K 素材并运行完整基准：

```powershell
.\scripts\benchmark-windows-gpu.ps1
```

使用真实素材：

```powershell
.\scripts\benchmark-windows-gpu.ps1 -InputPath "D:\素材\实际课程视频.mp4" -ReportName "real-course-4k"
```

真实素材建议 30～60 秒，优先选择平时真的会剪的 4K H.264 或 HEVC 文件。不需要专门寻找 8K 素材。
